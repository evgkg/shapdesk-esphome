# Shapdesk Wi-Fi + Home Assistant

Новый проект ESPHome для ESP32-C3 SuperMini. Управление через нативный зашифрованный API, автообнаружение mDNS, OTA, резервная точка доступа и captive portal. MQTT не используется. Парсер, оценка физической высоты и контроллер движения отделены от ESPHome и проверяются на ПК. Версия ESPHome закреплена в `requirements.txt`.

## Подключение

| Контакт | GPIO | Назначение |
|---|---:|---|
| K1 | 5 | Вверх |
| K2 | 6 | Вниз |
| K3 | 7 | Пресет 1, проверить соответствие |
| K4 | 10 | Пресет 2, проверить соответствие |
| K5 | 0 | Пресет 3, проверить соответствие |
| K6 | 1 | Пресет 4, проверить соответствие |
| K7 | 3 | M |
| RX UART1 | 4 | Линия RX пульта через делитель 10k/18k, 9600 8N1 |
| USB | 18/19 | USB Serial/JTAG, не использовать для кнопок |

Каждый GPIO через 4.7 кОм управляет базой MMBT3904; между базой и эмиттером 100 кОм. Транзистор включён параллельно соответствующей физической кнопке. HIGH нажимает, LOW отпускает. Питание по данным владельца: 5 В пульта → ME6211 → 3.3 В, USB может быть подключён одновременно. GPIO2/8/9/20/21 не используются. UART TX не назначен; код ничего в UART не передаёт. Штатные кнопки и защиты контроллера сохраняются.

## Установка

В PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item secrets.example.yaml secrets.yaml
```

В `secrets.yaml` задайте Wi-Fi, пароли OTA/AP и собственный случайный API-ключ. Значения шаблона публичные, их необходимо заменить. Создать ключ:

```powershell
.\.venv\Scripts\python -c "import secrets,base64; print(base64.b64encode(secrets.token_bytes(32)).decode())"
.\.venv\Scripts\esphome config shapdesk.yaml
.\.venv\Scripts\esphome compile shapdesk.yaml
```

Первую прошивку выполняет владелец через USB, указав фактический COM-порт:

```powershell
.\.venv\Scripts\esphome upload shapdesk.yaml --device COM3
.\.venv\Scripts\esphome logs shapdesk.yaml --device COM3
```

Последующие обновления после компиляции:

```powershell
.\.venv\Scripts\esphome upload shapdesk.yaml --device shapdesk.local
```

Если mDNS недоступен, укажите IP. При недоступном Wi-Fi подключитесь к `Shapdesk Fallback` с паролем из secrets и настройте сеть через captive portal. Перед OTA все выходы отпускаются. При необходимости входа в загрузчик используйте BOOT/RESET своей платы; GPIO9 не занят прошивкой.

В Home Assistant откройте «Настройки → Устройства и службы»: устройство обнаруживается как ESPHome. Добавьте его, указав API-ключ. При отсутствии автообнаружения добавьте интеграцию ESPHome вручную по IP, порт 6053.

## Сущности и команды

* «Высота стола» — физическая оценка в см; неизвестная, устаревшая или удержанная оценка публикуется NaN.
* «Высота на дисплее», Position raw (изначально отключён), счётчики валидных/отвергнутых пакетов, RSSI и uptime — диагностика.
* «Стол движется» — эвристика изменения raw, без данных состояние неизвестно; «Связь с пультом» — валидная AA+STATE за последнюю секунду.
* Cover «Стол»: открыть — K1, закрыть — K2, стоп — отпустить всё. Промежуточная позиция — движение на соответствующую высоту.
* «Целевая высота» — движение на высоту с шагом 1 см, включая крайние значения.
* Кнопки пресетов K3–K6, M и «Стоп».
* API action `esphome.shapdesk_press_key` принимает целые `key` (1–7) и `duration_ms`. Например, `{key: 7, duration_ms: 300}`. Фактическое имя действия зависит от имени узла в HA. Ошибочные параметры отвергаются с записью в лог.

ESPHome CoverCall представляет OPEN и позицию 100% одинаково; CLOSE и 0% тоже. Поэтому 0/100% используют ограниченное ручное движение, как штатные open/close. Для замкнутого движения точно на минимум/максимум используйте «Целевая высота». Это ограничение API ESPHome, отражённое в отчёте.

## Настройки substitutions

| Параметр | По умолчанию | Смысл |
|---|---:|---|
| `k3_name`…`k6_name` | Пресет 1…4 | Проверить порядок на своём пульте |
| `max_hold_ms` | 20000 | Общий предел K1/K2/K7, 1…120000 мс |
| `pulse_ms` | 300 | Короткое нажатие, 1…500 мс |
| `start_timeout_ms` | 3000 | Ожидание начала движения, 1…30000 мс |
| `min_height`, `max_height` | 66, 131 | Программные пределы, внутри 50…150 см |
| `tolerance` | 1 | Допуск цели, 0…5 см |
| `stop_offset` | 1 | Начальное упреждение, 0…5 см |
| `adapt_offset` | true | Подстройка по измеренному выбегу |

Упреждение хранится отдельно для направлений в RAM, без восстановления после перезагрузки. После остановки и 500 мс без движения измеряется выбег. Обновление: `0.75 × старое + 0.25 × выбег`, диапазон 0…5 см. Образец с потерянной/удержанной высотой, обратным движением или выбегом вне 0…5 отбрасывается. Новая команда отменяет обучение предыдущего движения.

## Ограничения и отказоустойчивость

Все выходные защёлки очищаются до включения GPIO, настройка выполняется до Wi-Fi. Внешние резисторы удерживают базы при сбросе. Нажатия при загрузке/восстановлении отсутствуют. Максимум один GPIO HIGH; после отпускания обязательна пауза минимум 50 мс. Повторная команда не продлевает текущий дедлайн, конфликтующая отпускает всё и отвергается — повторить её можно отдельным действием после паузы.

GPTimer проверяет абсолютный дедлайн каждую 1 мс и напрямую очищает GPIO в ISR независимо от loop и логирования. K3–K6 дополнительно ограничены 500 мс в схеме и C++, включая прямые API-вызовы. Точность ограничена квантованием и задержкой прерываний; электрическую длительность необходимо измерить на плате. Полная остановка CPU/прерываний и неисправности транзисторов не покрываются программной гарантией.

Движение на высоту требует свежей (≤1 с), неудержанной оценки. Во время него отсутствие валидных AA+STATE >500 мс, удержанная высота, неправильное направление, таймаут старта, предел или потеря API/Wi-Fi отпускают всё. Жёсткий дедлайн действует всегда. Без UART разрешены только ограниченные ручные команды. Программные пределы работают по свежей физической оценке, движение от предела разрешено. Ошибки UART/переполнение/большая очередь сбрасывают оценку и отпускают выходы.

«Стоп» отпускает электронные контакты. Он не может отменить физически удержанную кнопку и не гарантирует прекращение автоматического движения, которое штатный пульт начал после короткого вызова пресета. Необходимо сохранять доступ к штатным средствам остановки.

## Первая проверка владельцем

1. До движения проверьте LOW всех семи выходов при загрузке, сбросе и переподключении, независимый таймаут осциллографом/анализатором, работу физических кнопок и показания высоты.
2. Коротко нажмите K7 (300 мс). Затем отдельно K1 и K2 по 300 мс через API; между командами выдерживайте паузу. Проверьте отпускание по «Стоп», потере API/Wi-Fi, дедлайну и перед OTA.
3. Убедитесь, что высота совпадает с дисплеем в покое. Проверьте переход пресета: его краткое значение не должно стать физической высотой.
4. В свободной зоне выполните перемещение на 2–3 см. Измерьте задержку пробуждения и выбег, подстройте настройки. Проверьте оба направления и пределы с возможностью немедленной штатной остановки.
5. Сопоставьте K3–K6 пресетам и переименуйте substitutions. Длительное удержание пресетов запрещено.

## Хост-тесты

Нужен нативный C++20-компилятор, CMake и Ninja:

```powershell
cmake -S . -B build/host -G Ninja
cmake --build build/host
ctest --test-dir build/host --output-on-failure
```

Перенесены тесты исходного парсера, checksum, tracking, rejection и diagnostics; добавлена симуляция управления с управляемым временем. Для Windows без C++-компилятора можно установить `ziglang` через pip и задать CMake `CMAKE_CXX_COMPILER` как путь к `zig.exe`, `CMAKE_CXX_COMPILER_ARG1=c++`.
